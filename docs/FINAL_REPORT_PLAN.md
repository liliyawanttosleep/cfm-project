> 写于 2026-11-07（第二版，取代同日的 R1–R7 版本）。

## 1. 主线和范围

**一句话**：CFM 把生成变成回归，采样就是解一个 ODE。采样的代价是 NFE，质量取决于 ODE 的路径有多弯、解得有多准。所以“优化效率”只有三条路，“检测质量”需要一套可靠的指标：

```
             训练端（改变网络学到的场）                         推理端（改变怎样解 ODE）
  ┌───────────────┬────────────────┬─────────────┐     ┌──────────────────────────┐
  │ 配对 q(x0,x1)  │ 训练时间 t 的分布 │ 再训练拉直    │ →   │ 求解器阶数 + 时间网格       │ → 样本
  │ I-CFM / OT    │ uniform / logit │ reflow      │     │ Euler / Heun / RK4        │
  │ OT batch 大小  │ -normal         │             │     │ 均匀 / shift / 按曲率分配   │
  └───────────────┴────────────────┴─────────────┘     └──────────────────────────┘
        C3                C4              C5                       C2
                                      ↓ 所有模型、所有设置
          质量检测（C1）：FID · 类别覆盖（k-means + χ²，课程方法）· 直线度 · 代价（NFE、训练时间）
                                      ↓
                 综合（C6）：质量–效率前沿；直线度能否预测少步质量
```

**做什么**：上图中的 C1–C6，必要时用 CIFAR-10 官方权重验证（C7）。
**不做什么**：新的 diffusion 实验、第二个数据集、分类器类的评估方法（理由见第 7 节）。

## 4. 统一评估协议（所有实验共用）

**质量指标**
- **FID**：clean-fid，10,000 张，同一份参考集（MNIST 训练集），同一份采样噪声（`torch.manual_seed(100)`）。真实 vs 真实 = 0.54。
- **类别覆盖**（课程方法）：k-means（k = 10）只在真实图上拟合，生成图分到最近的中心，报告 TV、χ²、效应量 w。真实测试集基线 TV = 0.017。
- **直线度**：路径长度比（100 步 Euler 的路径长度 / 首尾距离，1 = 直线）和 S = E‖(x₁ − x₀) − v(x_t, t)‖²。

**效率指标**
- **NFE 为主要代价**（和硬件无关）。Heun 每步 2 次调用，RK4 每步 4 次，一律按网络调用次数计。
- **达标步数**：NFE@20 = FID 首次 ≤ 20 所需的最少 NFE；NFE@1.1× = FID 首次不超过该模型 dopri5 FID 的 1.1 倍所需的 NFE。两者在对数 NFE 上插值。
- **训练代价**：GPU 分钟，包括 OT 求解和 reflow 生成配对的时间。
- **计时规则**：实验平时用限速运行（`--duty 0.5`），计时会变长，所以**不用正式实验的计时**。另做一次不限速（`--duty 1`）的短基准，测每个设置每 1,000 张的秒数和每个 epoch 的秒数。

**可靠性**
- 基础模型（I-CFM、OT-CFM）用 3 个训练种子；新变体（C3–C5）先用种子 0，结果接近时再补种子 1。
- 对每个结论报告两种误差：**训练种子之间的波动**和**同一模型换采样噪声的波动**（C1 测）。差异小于训练种子标准差的，不写成“更好”。
- 只有 3 个种子时不做显著性检验，只报告“三个种子方向是否一致”和均值 ± 标准差。

## 5. 实验

每个实验写：**目的、设计流程、理想结果、要验证的问题、判定方法、成本、负责人、输出**。理想结果是事先的假设；实际结果不同时如实写，并按判定方法解释。

### C1. 质量检测的可靠性（必做）

- **目的**：后面每个“改进”都要和误差比较，所以先量清楚误差，并说明 FID 之外为什么还要看类别覆盖和直线度。
- **设计流程**
  1. I-CFM、OT-CFM 训练第 3 个种子（`train_mnist.py --seed 2`，设定和种子 0、1 相同）；Euler NFE 1 / 2 / 5 / 10 / 20 / 50 / 100 和 dopri5。
  2. **采样噪声误差**：种子 0 的两个模型，在 NFE 2、10、100 时换 5 份采样噪声，各算一次 FID 和 TV。
  3. **样本数的影响**：同一模型在 NFE 100 时用 2k / 5k / 10k / 20k 张算 FID，说明 10k 的偏差有多大。
  4. **类别覆盖的统计**：`cluster_coverage.py` 额外保存每簇计数；TV 的 bootstrap 95% 区间（1,000 次）；k = 10 和 20 两种设置。
  5. **直线度**：三个种子都算路径长度比和 S，看它在训练种子之间是否稳定（C6 要用它做预测变量）。
- **理想结果**
  - 采样噪声引起的 FID 波动 < 1，远小于训练种子之间的波动（两个种子在 100 步时相差 1.6–2.9）。
  - 1–2 步时 OT-CFM 在三个种子上都优于 I-CFM；10 步以后两者差距落在种子波动之内。
  - 直线度在种子之间的波动小于两种方法之间的差别。
- **要验证的问题**：RQ1。FID 和 TV 的误差有多大？后面实验中多大的差距才算“改进”？
- **判定方法**：定下“改进门槛”= 2 × 训练种子标准差，后面所有实验统一使用。
- **成本**：训练 2 × 35 分钟（限速约 55 分钟）；评估约 2 小时。
- **负责**：A（模型和 FID），B（类别覆盖的统计）。
- **输出**：`results/c1_reliability/`。

### C2. 推理端优化：求解器和时间网格（必做，不需要训练）

- **目的**：最便宜的优化。已有模型不动，只换解 ODE 的方式，看固定 NFE 下能提升多少。
- **设计流程**
  1. 求解器：Euler（1 阶）、Heun（2 阶）、RK4（4 阶）。NFE ∈ {2, 4, 8, 16, 32}（Heun 从 2 开始，RK4 从 4 开始）。
  2. 时间网格（N 步时的 t₀ < … < t_N）：
     - 均匀网格（现在用的）；
     - shift 网格：t′ = s·t / (1 + (s − 1)·t)，s ∈ {0.5, 2}，分别把步子集中在 t = 1 附近和 t = 0 附近；
     - **按曲率分配**（我们自己的方法）：先用 dopri5 轨迹测每个 t 处的速度变化率 κ(t) = E‖dv/dt‖，再让每一步分到相同的 ∫√κ dt。这个网格每个模型只算一次（用 256 条轨迹），之后反复使用。
  3. 模型：I-CFM 和 OT-CFM 种子 0；C5 的 reflow 模型做完后再跑一遍。
  4. 每个设置算 FID；最好的两三个设置再算 TV。
- **理想结果**
  - Heun 在 8–16 次调用时明显好于同样调用次数的 Euler；2 次调用时帮助不大（只有 1 个 Heun 步）。
  - 按曲率分配的网格在 4–16 步时优于均匀网格；曲率集中在哪一段可以直接画出来（预计在 t 的中后段：slide 16 的 1D 例子中，路径先朝数据均值走，之后才转弯）。
  - **路径越弯，好求解器的收益越大**：I-CFM 上的收益大于 OT-CFM，reflow 之后最小。
- **要验证的问题**：RQ2。不重新训练，NFE@20 能下降多少？
- **判定方法**：在同一 NFE 下和均匀网格 Euler 比较，差距超过 C1 的改进门槛才算改进。
- **成本**：约 3–4 小时 GPU（每个设置 1–2 分钟）。
- **负责**：A（求解器、网格），B（κ(t) 的测量和作图）。
- **输出**：`results/c2_solvers/`；新脚本 `code/c2_solvers/sample_grid.py`。

### C3. 训练端：配对和 OT batch 大小（应做）

- **目的**：报告的结论是 OT 优势在 784 维消失。要分清原因：是 batch 128 太小，还是能节省的代价本来就很少（slide 27 的推算：上限 2 tr Σ^½ = 386，总代价约 1,509）。
- **设计流程**
  1. 只测配对（CPU）：OT batch = 128、256、512、1,024、2,048、4,096，比较 OT 配对和随机配对的平均代价，画“节省比例 vs batch 大小”，和上限对照。
  2. 训练：OT-CFM，训练 batch 仍为 128，OT 计划在 512 和 2,048 个样本上求解，再分成小 batch 使用（需要给 `train_mnist.py` 加 `--ot-batch`）。种子 0。
  3. 评估：Euler NFE 1 / 2 / 5 / 10 / 20 的 FID、直线度；记录 OT 求解增加的训练时间。
- **理想结果**：节省比例随 batch 增大而缓慢上升，到 2,048 时仍低于 10%；1–2 步的 FID 略有改善，5 步以上没有可分辨的差别；训练时间增加 20–50%。
- **要验证的问题**：RQ3。在高维中靠“更好的配对”提升少步质量值不值得？
- **判定方法**：如果 2,048 时节省比例仍低于 10%，并且 FID 改善低于改进门槛，就结论为“主要原因是能节省的部分本来就少”，配对这条路在高维中不划算。
- **成本**：配对测量约 30 分钟（CPU）；训练 2 × 约 1.2 小时；评估约 40 分钟。
- **负责**：A。
- **输出**：`results/c3_otbatch/`。

### C4. 训练端：训练时间 t 的分布（应做）

- **目的**：CFM 训练时 t 从 U[0, 1] 均匀抽取。SD3 论文（Esser 2024，papers/30）发现把 t 集中在中段的 logit-normal 分布效果更好，但也发现有的设置在 50 步时最好、5 步时很差。我们的少步场景正好可以检验这一点。这和 C2 的曲率测量是同一个问题：中段 t 最难学，是不是也是路径最弯的地方？
- **设计流程**
  1. 两种分布：logit-normal(0, 1)（SD3 推荐的默认设置）；**按 C2 测到的曲率 κ(t) 加权**（我们的变体，在路径弯的地方多训练）。
  2. 模型：I-CFM，种子 0（需要给 `train_mnist.py` 加 `--t-dist`）。结果明显时再用 OT-CFM 做一次。
  3. 评估：Euler NFE 1–100 的 FID、dopri5 的 FID、直线度；C2 中最好的网格也跑一遍。
- **理想结果**：logit-normal 在 10–50 步时比 uniform 好，1–2 步时不一定好（SD3 中也有这种现象）；按曲率加权的分布在少步时至少不差于 logit-normal。
- **要验证的问题**：RQ3。不改配对，只改“在哪些 t 上多学”，能否提升少步质量？
- **判定方法**：和 C1 中 I-CFM 三个种子的范围比较，落在范围之外才算改变。
- **成本**：训练 1–2 × 35 分钟；评估约 40 分钟。
- **负责**：B。
- **输出**：`results/c4_tdist/`。

### C5. 拉直：Reflow（必做，体现复杂度的主实验）

- **目的**：OT 配对在高维中不够用时，reflow 用模型自己生成的配对 (x₀, x̂₁) 再训练一次，不受 batch 大小限制，直接把路径拉直。这是少步生成的核心办法（backup B4 只讲了原理）。同时要算清代价：生成配对和再训练都要时间。
- **设计流程**
  1. 用 I-CFM 种子 0，从 60,000 份噪声 x₀ 出发，dopri5 积分得到 x̂₁（约 70 分钟），保存配对。
  2. 同一个 U-Net、同样 50 epoch，在配对上用直线目标 x̂₁ − x₀ 训练 2-rectified flow（约 35 分钟）。可以从 I-CFM 的权重开始微调，再比较从头训练的版本。
  3. 评估：Euler NFE 1 / 2 / 5 / 10 / 20 / 100 和 dopri5 的 FID；直线度；类别覆盖 TV；C2 的求解器和网格。
  4. 对照：从 OT-CFM 种子 0 出发再做一次 reflow，看两种起点是否收敛到相近的结果。
  5. 配对代价：reflow 配对的 E‖x₀ − x̂₁‖² 和随机配对、minibatch OT 配对放在同一张表里（接 C3）。
  6. 代价核算：生成配对 + 再训练的 GPU 时间，换算成“每节省一次 NFE 要多花多少训练时间”。
- **理想结果**
  - 1 步 FID 从 I-CFM 的约 330 降到几十（文献在 CIFAR 上从 378 降到 12.2）；路径长度比接近 1；NFE@20 从 I-CFM 的 20–50 降到 5 以下。
  - 多步时 FID 略差于原模型（配对来自模型，误差会传下去），类别覆盖 TV 不变差。
  - reflow 之后，Heun 相对 Euler 的收益几乎消失（路径已经直了）。
- **要验证的问题**：RQ3。在 784 维中，reflow 能否做到 minibatch OT 做不到的少步生成？质量和训练代价各付出多少？
- **判定方法**：1 步 FID 低于两个原模型三个种子的最小值才算成功；多步时的损失用改进门槛衡量。
- **成本**：约 2.5 小时（限速约 4 小时），约 3 GB 硬盘存配对（不进 git）。
- **负责**：A。
- **输出**：`results/c5_reflow/`。

### C6. 综合分析：质量–效率前沿和直线度诊断（必做，只做分析）

- **目的**：把 C1–C5 的所有模型和采样设置放在一起，回答“哪种办法最划算”和“能否事先判断一个模型需要多少步”。
- **设计流程**
  1. **前沿图**：横轴 NFE（对数），纵轴 FID，每个（模型 × 求解器 × 网格）一条线，画出下包络线（前沿）。
  2. **达标步数表**：每个设置的 NFE@20、NFE@1.1×，以及训练代价。
  3. **直线度诊断**：所有模型的路径长度比（或 S）对 1 步、2 步 FID 和 NFE@20 作散点图，报告 Spearman 相关。
  4. **能否叠加**：比较“只做训练端改进”“只做推理端改进”“两者都做”的 NFE@20。
  5. **TV vs FID**：所有设置的 TV 和 FID 的散点图，说明类别覆盖提供了 FID 没有的信息。
- **理想结果**：直线度和少步 FID 强相关（越直，少步越好）；前沿主要由“reflow + 好网格”构成；训练端和推理端的改进部分可以叠加；TV 和 FID 在少步时一致，在多步时不一致。
- **要验证的问题**：RQ4。
- **判定方法**：模型数量少（约 8–10 个），相关系数只作描述，不做检验。
- **成本**：几小时作图和写作，不需要 GPU。
- **负责**：共同。
- **输出**：`results/c6_summary/`，作为 report 的主图和主表。

### C7. CIFAR-10 验证（选做）

- **目的**：MNIST 模型只训练了 50 epoch、没有 EMA（最好 FID 11.5），还是“演示级”。CIFAR-10 的官方权重训练了 400k 步，可以检查 C2 的推理端结论在训练充分、维度更高（3,072）的模型上是否成立。不需要训练。
- **设计流程**：官方 I-CFM、OT-CFM 权重；Euler / Heun × 均匀 / 按曲率分配的网格，NFE 4 / 8 / 16 和 dopri5；10,000 张，clean-fid；3,072 维的配对代价（同 C3 第 1 步）。
- **理想结果**：按曲率分配的网格和 Heun 的收益方向与 MNIST 相同；dopri5 下两模型接近（文献 3.58 vs 3.66）；OT 配对节省比例比 MNIST 更低。
- **要验证的问题**：RQ2、RQ3 的结论是否只在 MNIST 上成立。
- **判定方法**：只有一个训练种子，只看方向是否和 MNIST 一致，不下强结论。
- **成本**：约 2 小时 GPU。
- **负责**：A。
- **输出**：`results/c7_cifar/`。
