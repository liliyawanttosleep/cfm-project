## 1. 主线和范围

**一句话**：CFM 把生成变成回归，采样就是解一个 ODE。采样的代价是 NFE，质量取决于 ODE 的路径有多弯、解得有多准。所以“优化效率”只有三条路，“检测质量”需要一套可靠的指标：

```
             训练端（改变网络学到的场）                         推理端（改变怎样解 ODE）
  ┌───────────────┬────────────────┬─────────────┐     ┌──────────────────────────┐
  │ 配对 q(x0,x1)  │ 训练时间 t 的分布 │ 再训练拉直    │ →   │ 求解器阶数 + 时间网格       │ → 样本
  │ I-CFM / OT    │ uniform / logit │ reflow      │     │ Euler / Heun / RK4        │
  │ OT batch 大小  │ -normal         │             │     │ 均匀 / shift / 曲率 / 校准  │
  └───────────────┴────────────────┴─────────────┘     └──────────────────────────┘
        C3                C4              C5                       C2
                                      ↓ 所有模型、所有设置
          质量检测（C1）：FID · 类别覆盖（k-means + χ²，课程方法）· 直线度 · 代价（NFE、训练时间）
                                      ↓
                 综合（C6）：质量–效率前沿；直线度能否预测少步质量
```

**做什么**：上图中的 C1–C6，必要时用 CIFAR-10 官方权重验证（C7）。
**不做什么**：新的 diffusion 实验、第二个数据集、分类器类的评估方法（理由见第 7 节）。

## 4. 统一评估协议（所有实验共用）

**质量指标**
- **FID**：clean-fid，10,000 张，同一份参考集（MNIST 训练集），同一份采样噪声（`torch.manual_seed(100)`）。真实 vs 真实 = 0.54。
- **类别覆盖**（课程方法）：k-means（k = 10）只在真实图上拟合，生成图分到最近的中心，报告 TV、χ²、效应量 w。真实测试集基线 TV = 0.017。
- **直线度**：路径长度比（100 步 Euler 的路径长度 / 首尾距离，1 = 直线）和 S = E‖(x₁ − x₀) − v(x_t, t)‖²。

**效率指标**
- **NFE 为主要代价**（和硬件无关）。Heun 每步 2 次调用，RK4 每步 4 次，一律按网络调用次数计。
- **达标步数**：NFE@20 = FID 首次 ≤ 20 所需的最少 NFE；NFE@1.1× = FID 首次不超过该模型 dopri5 FID 的 1.1 倍所需的 NFE。两者在对数 NFE 上插值。
- **训练代价**：GPU 分钟，包括 OT 求解和 reflow 生成配对的时间。
- **计时规则**：实验平时用限速运行（`--duty 0.5`），计时会变长，所以**不用正式实验的计时**。另做一次不限速（`--duty 1`）的短基准，测每个设置每 1,000 张的秒数和每个 epoch 的秒数。

**可靠性**
- 基础模型（I-CFM、OT-CFM）用 3 个训练种子；新变体（C3–C5）先用种子 0，结果接近时再补种子 1。
- 对每个结论报告两种误差：**训练种子之间的波动**和**同一模型换采样噪声的波动**（C1 测）。差异小于训练种子标准差的，不写成“更好”。
- 只有 3 个种子时不做显著性检验，只报告“三个种子方向是否一致”和均值 ± 标准差。

## 5. 实验

每个实验写：**目的、设计流程、理想结果、要验证的问题、判定方法、成本、负责人、输出**。理想结果是事先的假设；实际结果不同时如实写，并按判定方法解释。

### C1. 质量检测的可靠性（必做）

- **目的**：后面每个“改进”都要和误差比较，所以先量清楚误差，并说明 FID 之外为什么还要看类别覆盖和直线度。
- **设计流程**
  1. I-CFM、OT-CFM 训练第 3 个种子（`train_mnist.py --seed 2`，设定和种子 0、1 相同）；Euler NFE 1 / 2 / 5 / 10 / 20 / 50 / 100 和 dopri5。
  2. **采样噪声误差**：种子 0 的两个模型，在 NFE 2、10、100 时换 5 份采样噪声，各算一次 FID 和 TV。
  3. **样本数的影响**：同一模型在 NFE 100 时用 2k / 5k / 10k / 20k 张算 FID，说明 10k 的偏差有多大。
  4. **类别覆盖的统计**：`cluster_coverage.py` 额外保存每簇计数；TV 的 bootstrap 95% 区间（1,000 次）；χ² 改用两样本齐性检验（参照比例本身也是估计值）；TV 的噪声下限按 D8 的公式计算（k = 10、n = 10,000、m = 30,000 时约 0.014，模拟核对 0.0139）；k = 10 和 20 两种设置。
  5. **直线度**：三个种子都算路径长度比和 S，看它在训练种子之间是否稳定（C6 要用它做预测变量）。
- **理想结果**
  - 采样噪声引起的 FID 波动 < 1，远小于训练种子之间的波动（两个种子在 100 步时相差 1.6–2.9）。
  - 1–2 步时 OT-CFM 在三个种子上都优于 I-CFM；10 步以后两者差距落在种子波动之内。
  - 直线度在种子之间的波动小于两种方法之间的差别。
- **要验证的问题**：RQ1。FID 和 TV 的误差有多大？后面实验中多大的差距才算“改进”？
- **判定方法**：定下“改进门槛”= 2 × 训练种子标准差，后面所有实验统一使用。
- **成本**：训练 2 × 35 分钟（限速约 55 分钟）；评估约 2 小时。
- **负责**：A（模型和 FID），B（类别覆盖的统计）。
- **输出**：`results/c1_reliability/`。
- **结果（11/11，第 1、5 步；汇总见 `results/c1_reliability/summary.md`，由 `summarize_c1.py` 生成）**
  - **训练种子之间的波动比预想的大，主要来自 I-CFM 的种子 2**。它在每个 NFE 都明显更差：100 步 FID 23.7，种子 0、1 是 14.5 / 12.9；dopri5 是 20.1，种子 0、1 是 12.1 / 10.7。
    - 核对过：训练设置和种子 0、1 完全相同（同一 `t` 抽样、没有从中断处续跑），最后的 loss 也相同（0.169 vs 0.168）。所以这是真实的波动，不是程序错误。
    - 可能的原因：没有 EMA，用的是第 50 个 epoch 结束时的权重，单次权重的好坏有偶然性。
  - **按 2 × 训练种子标准差算的门槛**（100 步）：I-CFM 11.6，OT-CFM 3.8；dopri5 时 10.1 / 3.4。I-CFM 的门槛几乎全由种子 2 决定。
  - **OT-CFM 在 1–5 步时三个种子都优于 I-CFM**（配对差：1 步 −109 到 −110，2 步 −49 到 −56，5 步 −1 到 −19）。10 步以上三个种子的符号不一致，不能说哪个更好。这和 slide 上的说法一致。
  - **直线度在种子之间非常稳定**：路径长度比 I-CFM 1.0209–1.0222，OT-CFM 1.0100–1.0113。种子之间相差约 0.001，两种方法相差约 0.011。所以它可以作为 C6 的预测变量。
  - **对后面判定方法的影响（建议）**：C2 这类实验是在**同一个训练好的模型上**换求解器或网格，比较时训练种子的波动不进入差值（D8 的配对比较）。所以这类实验应该用两个标准：
    1. 差值超过采样噪声误差（第 2 步，正在测）；
    2. 在其他训练种子上方向相同（C2 的种子 1、2 复核，已排队）。
    - 2 × 训练种子标准差的门槛只用于比较**不同训练出来的模型**（C3、C4、C5，以及 OT-CFM vs I-CFM）。
  - **采样噪声误差很小**（第 2 步，`fid_noise.py`，种子 0，6 份噪声）：FID 的标准差在 NFE 2 / 10 / 100 时是 0.34 / 0.13 / 0.13（I-CFM）和 0.58 / 0.28 / 0.05（OT-CFM），比训练种子的标准差（1.9–7.1）小 10–100 倍。从训练种子的方差里扣掉它（D8）几乎不变。所以**同一模型上的配对比较，差 1 个 FID 点就已经超出噪声**。
  - **样本数的影响**（第 3 步，NFE 100，噪声种子 100）：

    | FID | 2k | 5k | 10k | 20k | 外推 FID∞（拟合 c/n） |
    |---|---|---|---|---|---|
    | I-CFM | 17.3 | 14.9 | 14.5 | 14.1 | 13.7 |
    | OT-CFM | 17.1 | 14.5 | 13.9 | 13.4 | 13.0 |

    - 10k 的 FID 比 FID∞ 高约 0.8–0.9，两个模型的偏差几乎一样，所以同样用 10k 张比较时偏差会抵消。
    - 2k 张的偏差是 +3.6，不同 2k 块之间的标准差约 0.5。所以 CIFAR 或时间紧的实验不能用 2k 张和 10k 张的结果混着比较。
    - 前 10k 张的 FID 和 E4 的数字完全相同（14.52、13.91），说明流程一致。
  - **类别覆盖（第 4 步，`results/c1_reliability/kmeans_c1.json`，k-means 只用真实图拟合）**：
    - **两样本 χ² 修正了基线**：真实测试集在 k = 10 时 TV = 0.017，接近 D8 的噪声下限 0.0136，两样本检验 p = 0.14（不拒绝）。原来的单样本检验把参照比例当成已知，p = 0.037，会错误地说真实图“不均衡”。
    - k = 20 时真实测试集也被拒绝（TV 0.046，p ≈ 10⁻¹¹）。可能是 MNIST 训练集和测试集的写法略有差异，k = 20 的细簇能看出来。所以 k = 20 只作稳健性检查，主结果用 k = 10。
    - **TV 的误差**：bootstrap 95% 区间宽约 0.02；同一模型换 3 份噪声，TV 的标准差约 0.005；训练种子之间的标准差约 0.02–0.045。**TV 的改进门槛约 0.045–0.05**（100 步）。
    - **1–2 步时 OT-CFM 的覆盖远好于 I-CFM**：1 步 TV 0.08–0.14 vs 0.70–0.79，三个种子一致。100 步时两者的差别（OT-CFM 0.049 / 0.076 / 0.091，I-CFM 0.092 / 0.054 / 0.098）方向不一致，落在门槛之内。
    - **FID 和 TV 测的是不同的东西**：I-CFM 种子 2 的 FID 很差（23.7），但 TV（0.098）和种子 0（0.092）差不多。说明种子 2 差在图像质量，不是类别比例。这正是报告里“FID 之外为什么还要看类别覆盖”的例子。
  - **C1 结论（给后面的实验用）**：
    - 比较不同训练出来的模型：FID 门槛 = 2 × 训练种子标准差（100 步 I-CFM 11.6、OT-CFM 3.8），TV 门槛约 0.05。I-CFM 的门槛偏大，因为三个种子里有一个明显差。
    - 同一模型换采样设置：看差值是否超过采样噪声（FID 约 0.1–0.6），以及在种子 1、2 上方向是否相同。
    - 图：`results/c1_reliability/figs/c1_fid_seeds.png`。

### C2. 推理端优化：求解器和时间网格（必做，不需要训练）

- **目的**：最便宜的优化。已有模型不动，只换解 ODE 的方式，看固定 NFE 下能提升多少。
- **设计流程**
  1. 求解器：Euler（1 阶）、Heun（2 阶）、RK4（4 阶）。NFE ∈ {2, 4, 8, 16, 32}（Heun 从 2 开始，RK4 从 4 开始）。
  2. 时间网格（N 步时的 t₀ < … < t_N）：
     - 均匀网格（现在用的）；
     - shift 网格：t′ = s·t / (1 + (s − 1)·t)，s ∈ {0.25, 0.5, 2, 4}。s > 1 让步子集中在数据端（t = 1 附近），s < 1 集中在噪声端（t = 0 附近）；
     - **按曲率分配**：先用 dopri5 轨迹测速度沿路径的变化率 κ(t) = E‖dv/dt‖，再让每一步分到相同的 ∫√κ dt（推导见 `docs/notes/derivations.md` D5），并由 κ 预测误差比 G；
     - **校准网格**（我们的实用方法）：对每个 NFE，用 256 条 dopri5 路径作参照，从上面的候选网格中选终点误差最小的一个，再用它算 FID。
  3. 每个设置同时记录**终点误差**（和同一 x₀ 的 dopri5 终点的 RMS 距离）和 FID，检验终点误差能否预测 FID。
  4. 模型：I-CFM 和 OT-CFM 种子 0；C5 的 reflow 模型做完后再跑一遍。
  5. 每个设置算 FID；最好的两三个设置再算 TV。
- **理想结果**
  - Heun 在 8–16 次调用时明显好于同样调用次数的 Euler；2 次调用时帮助不大（只有 1 个 Heun 步）。
  - 校准网格在 2–16 步时不差于任何固定规则，并且明显好于均匀网格。
  - 按曲率分配的网格不一定好：1D 核对中，目标分布平滑时它比均匀网格的误差低 8–9%（预测 5%）；目标是两个点时反而差很多，因为最后一大步落在还没收敛的后验均值上（D3）。MNIST 落在哪一边是这个实验要回答的。
  - **路径越弯，好求解器的收益越大**：I-CFM 上的收益大于 OT-CFM，reflow 之后最小。
- **要验证的问题**：RQ2。不重新训练，NFE@20 能下降多少？
- **判定方法**：在同一 NFE 下和均匀网格 Euler 比较，差距超过 C1 的改进门槛才算改进。
- **成本**：约 3–4 小时 GPU（每个设置 1–2 分钟）。
- **负责**：A（求解器、网格），B（κ(t) 的测量和作图）。
- **输出**：`results/c2_solvers/`；新脚本 `code/c2_solvers/sample_grid.py`。
- **结果（11/10，种子 0，FID 用 1 万张；汇总见 `results/c2_solvers/summary.md` 和 `figs/`，由 `summarize_c2.py` 生成）**
  - **曲率**：两个模型的 κ(t) 都在 t > 0.95 陡升约 100 倍，∫κ 有 65–69% 落在 t > 0.9；D5 的预测误差比 G = 0.50（OT-CFM）、0.54（I-CFM）。路径前半段 OT-CFM 的 κ 比 I-CFM 低，和“OT 路径更直”一致。
  - **按曲率分配的网格（√κ）在 8 次调用以上一致地降低 FID**，2–4 次时和均匀网格持平或略差：

    | Euler FID | NFE 2 | 4 | 8 | 16 | 32 |
    |---|---|---|---|---|---|
    | OT-CFM 均匀 | 76.0 | 32.3 | 20.5 | 17.4 | 16.2 |
    | OT-CFM √κ | 86.3 | 32.8 | 19.7 | **14.3** | **12.5** |
    | I-CFM 均匀 | 131.9 | 56.6 | 32.0 | 22.4 | 18.4 |
    | I-CFM √κ | 132.7 | 60.6 | 31.3 | **19.8** | **15.2** |

    - dopri5 的 FID 是 11.5 / 12.1，要约 270 次调用。OT-CFM 用 Euler + √κ 只要约 30 次调用就到 dopri5 的 1.1 倍以内；均匀网格到 100 次（13.9）还没到。
    - NFE@20：OT-CFM 9.2 → 7.9，I-CFM 23.7 → 15.8（少 33%）。
  - **高阶求解器离不开好网格**：
    - 均匀网格上，Heun、RK4 在每个调用次数下都比 Euler 差得多（32 次时 50.4 / 40.7，Euler 是 16.2）。
    - 换成 √κ 网格后，32 次调用时三种求解器都到 12.5–13.3（I-CFM 13.2–15.2）。
    - 所以“换高阶求解器”本身不省调用次数，省次数的是网格。
  - **终点误差预测不了 FID**（`figs/c2_error_vs_fid.png`）：
    - 按终点误差校准，Euler 总是选 s ≈ 0.2–0.4（步子集中在噪声端）。这样终点误差最多低 30%，但 FID 在全部 10 个格子里都变差，例如 OT-CFM 2 步从 76.0 变成 108.8。
    - 同样终点误差下，s < 1 的网格 FID 系统性地更高。
    - 解释：终点 RMS 主要来自前期步骤的误差（决定“生成哪个数字”的大结构）；FID 对 t ≈ 1 附近决定的细节更敏感，而那里正是 κ 陡升的地方。
    - **结论**：校准的目标不能用终点误差。实用的规则就是 √κ，它只需要一次 dopri5 测 κ，不需要算 FID。
  - **t = 1 假设的检验（11/11 完成，`t1_check.py`，结果在 `results/c2_solvers/t1_*_s0.json`）**：假设成立。
    - **网络在 t = 1 处不准**：理想情况下 v(1, x) = x（因为 E[x₀] = 0）。在真实图上，RMS(v(1, x) − x) 是 0.41，而 RMS(x) 是 0.96，相对误差约 43%；在生成图上是 0.81 / 0.84（OT-CFM / I-CFM），约 85%。误差在 t = 0.9 时是 0.36，t = 0.999 时升到 0.57，越靠近 t = 1 越差。
    - **只改最后一步，高阶求解器就恢复正常**。heun_e 的最后一步用 Euler；rk4_e 的最后一步用 Heun，末端调用放在 1 − h/2。都用均匀网格时：

      | FID（均匀网格） | 原求解器 16 次 → 改最后一步 15 次 | 原求解器 32 次 → 改最后一步 31 / 30 次 |
      |---|---|---|
      | OT-CFM Heun | 83.3 → **15.5** | 50.4 → **15.9** |
      | OT-CFM RK4 | 66.1 → 16.4（14 次） | 40.7 → **16.5** |
      | I-CFM Heun | 78.4 → **17.8** | 48.0 → **16.5** |
      | I-CFM RK4 | 65.9 → 17.5（14 次） | 37.1 → **16.3** |

      差距是 30–70 个 FID 点，远大于训练种子之间的波动（100 步时 1.6–2.9），不需要等 C1 的门槛就能下结论。
    - **这也解释了 √κ 网格为什么能救高阶求解器**：√κ 网格的最后一步很短，t = 1 那次不准的调用权重只有 h/2，影响就小了。所以“高阶求解器离不开好网格”更准确的说法是：高阶求解器不能在 t = 1 处用网络。
    - **达标步数（NFE@20）**：OT-CFM 从 9.2（Euler 均匀）降到 6.6（heun_e 均匀），少 28%；I-CFM 从 23.7 降到 9.9（rk4_e 均匀），少 58%，也比 Euler + √κ 的 15.8 少。到 dopri5 的 1.1 倍：heun_e + √κ 只要约 30 次（OT-CFM 29.7，I-CFM 28.2）。
    - **调用次数多时差别变小**：31 次时 heun_e + √κ 是 12.4 / 12.9，Euler + √κ 32 次是 12.5 / 15.2。OT-CFM 两者持平；I-CFM 差 2.3，要和 C1 的门槛比较后才能说是改进。
    - OT-CFM 的均匀网格在 15–32 次调用之间停在 FID ≈ 16（Euler 17.4 → 16.2，heun_e 15.5 → 15.9，rk4_e 16.4 → 16.5），√κ 网格继续降到 12.4。所以剩下的差距来自 t ≈ 1 附近的步子不够密，而不是求解器的阶数。I-CFM 同样：heun_e / rk4_e 均匀网格约 16.4，√κ 12.9。
  - **还要做**：
    - 种子 1 复核（`sample_grid.py --core --seed 1`）；
    - C1 测出采样噪声误差后，判断 16–32 次调用时 2–4 的 FID 差距，以及 I-CFM heun_e 和 Euler 在 31–32 次时的 2.3，是否超过改进门槛。
  - **补充（终点误差和 FID 的一致性）**：OT-CFM 同一求解器、同一调用次数下，任取两个网格比较，终点误差的高低和 FID 的高低只有 124 / 204 对一致（61%），接近随机。全部网格的 FID 见 `results/c2_solvers/summary.md` 和两个 JSON。

### C3. 训练端：配对和 OT batch 大小（应做）

- **目的**：报告的结论是 OT 优势在 784 维消失。要分清原因：是 batch 128 太小，还是能节省的代价本来就很少（slide 27 的推算：上限 2 tr Σ^½ = 386，总代价约 1,509）。
- **设计流程**
  1. 只测配对（CPU）：OT batch = 128、256、512、1,024、2,048、4,096，比较 OT 配对和随机配对的平均代价，画“节省比例 vs batch 大小”，和上限对照。
  2. 训练：OT-CFM，训练 batch 仍为 128，OT 计划在 512 和 2,048 个样本上求解，再分成小 batch 使用（需要给 `train_mnist.py` 加 `--ot-batch`）。种子 0。
  3. 评估：Euler NFE 1 / 2 / 5 / 10 / 20 的 FID、直线度；记录 OT 求解增加的训练时间。
- **理想结果**：节省比例随 batch 增大而缓慢上升，到 2,048 时仍低于 10%；1–2 步的 FID 略有改善，5 步以上没有可分辨的差别；训练时间增加 20–50%。
- **要验证的问题**：RQ3。在高维中靠“更好的配对”提升少步质量值不值得？
- **判定方法**：如果 2,048 时节省比例仍低于 10%，并且 FID 改善低于改进门槛，就结论为“主要原因是能节省的部分本来就少”，配对这条路在高维中不划算。
- **成本**：配对测量约 30 分钟（CPU）；训练 2 × 约 1.2 小时；评估约 40 分钟。
- **负责**：A。
- **输出**：`results/c3_otbatch/`。
- **结果（11/11，第 1 步；`code/c3_otbatch/pair_cost.py`，`results/c3_otbatch/pairs.json`，图 `figs/c3_saving_vs_batch.png`）**

  | OT batch | 16 | 64 | 128 | 256 | 512 | 1,024 | 2,048 | 4,096 |
  |---|---|---|---|---|---|---|---|---|
  | 省下的代价 | 43.7 | 60.3 | 67.7 | 73.2 | 79.1 | 84.1 | 87.7 | 92.4 |
  | 占随机配对代价（约 1,510） | 2.9% | 4.0% | 4.5% | 4.8% | 5.2% | 5.6% | 5.8% | 6.1% |
  | 占上限 2 tr Σ^½ = 386 | 11% | 16% | 18% | 19% | 21% | 22% | 23% | 24% |
  | 一次 OT 求解（秒） | 0.0003 | 0.0005 | 0.002 | 0.007 | 0.04 | 0.15 | 1.2 | 6.2 |

  - batch 每翻一倍只多省约 6（0.4%）。按对数拟合，要省到总代价的 10%，batch 要约 280 万，远超训练集的 6 万张；即使用整个训练集求 OT，也只省约 7.8%。拟合在大 batch 处略偏乐观，所以实际只会更少。
  - 已经满足判定标准的前一半：2,048 时节省比例 5.8%，低于 10%。是否“配对这条路在高维中不划算”，还要看第 2、3 步的 FID。
  - 训练成本的估计：每 2,048 个样本求一次 OT（1.2 秒），每个 epoch 约 29 次，多约 35 秒，约占限速后一个 epoch（85 秒）的 40%；4,096 时多约 90 秒，翻倍。
  - **第 2、3 步已排队**：OT-CFM `--ot-batch 512` 和 `2048`（种子 0），各自训练完后用 `fid_seed.py --seed 0 --tag _otb{B} --dopri` 评估（Euler 1–100 步、dopri5、直线度）。比较对象是 OT-CFM 种子 0–2，门槛用 C1 的 2 × 训练种子标准差。

### C4. 训练端：训练时间 t 的分布（应做）

- **目的**：CFM 训练时 t 从 U[0, 1] 均匀抽取。SD3 论文（Esser 2024，papers/30）发现把 t 集中在中段的 logit-normal 分布效果更好，但也发现有的设置在 50 步时最好、5 步时很差。我们的少步场景正好可以检验这一点。这和 C2 的曲率测量是同一个问题：中段 t 最难学，是不是也是路径最弯的地方？
- **设计流程**
  1. 两种分布：logit-normal(0, 1)（SD3 推荐的默认设置）；**按 C2 测到的曲率 κ(t) 加权**（我们的变体，在路径弯的地方多训练）。
  2. 模型：I-CFM，种子 0（需要给 `train_mnist.py` 加 `--t-dist`）。结果明显时再用 OT-CFM 做一次。
  3. 评估：Euler NFE 1–100 的 FID、dopri5 的 FID、直线度；C2 中最好的网格也跑一遍。
- **理想结果**：logit-normal 在 10–50 步时比 uniform 好，1–2 步时不一定好（SD3 中也有这种现象）；按曲率加权的分布在少步时至少不差于 logit-normal。
- **要验证的问题**：RQ3。不改配对，只改“在哪些 t 上多学”，能否提升少步质量？
- **判定方法**：和 C1 中 I-CFM 三个种子的范围比较，落在范围之外才算改变。
- **成本**：训练 1–2 × 35 分钟；评估约 40 分钟。
- **负责**：B。
- **输出**：`results/c4_tdist/`。

### C5. 拉直：Reflow（必做，体现复杂度的主实验）

- **目的**：OT 配对在高维中不够用时，reflow 用模型自己生成的配对 (x₀, x̂₁) 再训练一次，不受 batch 大小限制，直接把路径拉直。这是少步生成的核心办法（backup B4 只讲了原理）。同时要算清代价：生成配对和再训练都要时间。
- **设计流程**
  1. 用 I-CFM 种子 0，从 60,000 份噪声 x₀ 出发，dopri5 积分得到 x̂₁（约 70 分钟），保存配对。
  2. 同一个 U-Net、同样 50 epoch，在配对上用直线目标 x̂₁ − x₀ 训练 2-rectified flow（约 35 分钟）。可以从 I-CFM 的权重开始微调，再比较从头训练的版本。
  3. 评估：Euler NFE 1 / 2 / 5 / 10 / 20 / 100 和 dopri5 的 FID；直线度；类别覆盖 TV；C2 的求解器和网格。
  4. 对照：从 OT-CFM 种子 0 出发再做一次 reflow，看两种起点是否收敛到相近的结果。
  5. 配对代价：reflow 配对的 E‖x₀ − x̂₁‖² 和随机配对、minibatch OT 配对放在同一张表里（接 C3）。
  6. 代价核算：生成配对 + 再训练的 GPU 时间，换算成“每节省一次 NFE 要多花多少训练时间”。
- **理想结果**
  - 1 步 FID 从 I-CFM 的约 330 降到几十（文献在 CIFAR 上从 378 降到 12.2）；路径长度比接近 1；NFE@20 从 I-CFM 的 20–50 降到 5 以下。
  - 多步时 FID 略差于原模型（配对来自模型，误差会传下去），类别覆盖 TV 不变差。
  - reflow 之后，Heun 相对 Euler 的收益几乎消失（路径已经直了）。
- **要验证的问题**：RQ3。在 784 维中，reflow 能否做到 minibatch OT 做不到的少步生成？质量和训练代价各付出多少？
- **判定方法**：1 步 FID 低于两个原模型三个种子的最小值才算成功；多步时的损失用改进门槛衡量。
- **成本**：约 2.5 小时（限速约 4 小时），约 3 GB 硬盘存配对（不进 git）。
- **负责**：A。
- **输出**：`results/c5_reflow/`。
- **结果（11/14，I-CFM 种子 0；`results/e3/fid_s0_reflow.json`，`results/c5_reflow/pairs_icfm_s0.json`）**
  - 配对：60,000 对，dopri5 平均 287 次调用，限速下 2.05 小时。配对代价 1,319，比随机配对省 12.7%，是上限的 50%；minibatch OT 在 batch 4,096 时只省 6.1%。
  - 训练：从 I-CFM 权重微调 50 epoch，限速下 1.08 小时；最终 loss 0.0038（原模型 0.168），说明确定性配对让 D1 中不可约的常数 C 几乎为 0。
  - FID（Euler）：1 步 332 → 64.6，2 步 132 → 30.9，5 步 45.3 → 23.9，10 步 27.9 → 22.6，20 步 20.7 → 22.0，100 步 14.5 → 20.5；dopri5 12.1 → 19.0。直线度 R 1.021 → 1.0008。
  - **达到判定标准**：1 步 FID 64.6，低于两个原模型三个种子的最小值（OT-CFM 205）。
  - **代价**：多步质量变差，100 步差 6.0、dopri5 差 6.9，按 I-CFM 门槛（11.6 / 10.1）不算“可分辨”，但从 20 步起每个 NFE 方向都一致；FID 20 在 100 步内达不到。总训练时间是原模型的 2.7 倍。
  - 解释：对精确的速度场，reflow 模型最好也只能复现原模型的样本（dopri5 FID 12.1）；多出的约 7 点是第二次回归的误差，叠加在第一次之上。
  - 前沿：reflow 在 1–2 步最好；约 5 步起，原模型配合改进的求解器更好。
  - 还在做：reflow 模型的类别覆盖 TV（CPU）；从 OT-CFM 出发的 reflow（已排队）；reflow 模型上的求解器 × 网格（`sample_grid.py --tag _reflow --core`，排在任务链之后，需要手动运行）。

### C6. 综合分析：质量–效率前沿和直线度诊断（必做，只做分析）

- **目的**：把 C1–C5 的所有模型和采样设置放在一起，回答“哪种办法最划算”和“能否事先判断一个模型需要多少步”。
- **设计流程**
  1. **前沿图**：横轴 NFE（对数），纵轴 FID，每个（模型 × 求解器 × 网格）一条线，画出下包络线（前沿）。
  2. **达标步数表**：每个设置的 NFE@20、NFE@1.1×，以及训练代价。
  3. **直线度诊断**：所有模型的路径长度比（或 S）对 1 步、2 步 FID 和 NFE@20 作散点图，报告 Spearman 相关。
  4. **能否叠加**：比较“只做训练端改进”“只做推理端改进”“两者都做”的 NFE@20。
  5. **TV vs FID**：所有设置的 TV 和 FID 的散点图，说明类别覆盖提供了 FID 没有的信息。
- **理想结果**：直线度和少步 FID 强相关（越直，少步越好）；前沿主要由“reflow + 好网格”构成；训练端和推理端的改进部分可以叠加；TV 和 FID 在少步时一致，在多步时不一致。
- **要验证的问题**：RQ4。
- **判定方法**：模型数量少（约 8–10 个），相关系数只作描述，不做检验。
- **成本**：几小时作图和写作，不需要 GPU。
- **负责**：共同。
- **输出**：`results/c6_summary/`，作为 report 的主图和主表。

### C7. CIFAR-10 验证（选做）

- **目的**：MNIST 模型只训练了 50 epoch、没有 EMA（最好 FID 11.5），还是“演示级”。CIFAR-10 的官方权重训练了 400k 步，可以检查 C2 的推理端结论在训练充分、维度更高（3,072）的模型上是否成立。不需要训练。
- **设计流程**：官方 I-CFM、OT-CFM 权重；Euler / Heun × 均匀 / 校准网格，NFE 4 / 8 / 16 和 dopri5；10,000 张，clean-fid；3,072 维的配对代价（同 C3 第 1 步）。
- **理想结果**：校准网格和 Heun 的收益方向与 MNIST 相同；dopri5 下两模型接近（文献 3.58 vs 3.66）；OT 配对节省比例比 MNIST 更低。
- **要验证的问题**：RQ2、RQ3 的结论是否只在 MNIST 上成立。
- **判定方法**：只有一个训练种子，只看方向是否和 MNIST 一致，不下强结论。
- **成本**：约 2 小时 GPU。
- **负责**：A。
- **输出**：`results/c7_cifar/`。
