## 3. 实验清单

每个实验写清楚五件事：**目的、设计流程、理想结果、最后要验证的问题、判定方法**。理想结果是我们事先的假设；实际结果不一样时如实写进 report，并按“判定方法”一栏解释。

优先级：**必做** = 不做 report 的结论就站不住；**应做** = 体现复杂度的主要部分；**选做** = 有时间再做。

### R1. 第三个训练种子 + 2D 补齐三个种子（必做）

- **目的**：报告里只有两个种子，而两个种子在 10 步以后和类别比例上都不一致。第三个种子可以判断是哪一个种子更“正常”，并给出均值 ± 标准差。
- **设计流程**
  1. MNIST：`train_mnist.py --method {icfm,otcfm,ddpm} --seed 2`，设定和种子 0、1 完全相同（50 epoch，batch 128，Adam，无 EMA）。
  2. `fid_seed.py --seed 2`：NFE 1 / 2 / 5 / 10 / 20 / 50 / 100，10,000 张，同一份参考集，同一份采样噪声（`torch.manual_seed(100)`）。
  3. `cluster_coverage.py --seeds 2`：E3 的 k-means 指标。
  4. **FID 的采样噪声误差**：对种子 0 的三个模型，在 NFE 1、5、100 时换 3 份采样噪声各算一次 FID，得到“同一个模型、只换噪声”的波动。这样可以把总波动拆成“训练种子”和“采样噪声”两部分。
  5. 2D：4 个数据集 × 5 个方法（加 Lipman FM）× 种子 1、2，用 `code/README.md` 里的循环命令。
- **理想结果**
  - 1–2 步时 OT-CFM 的 FID 在三个种子上都低于 I-CFM 和 DDIM。
  - 10 步以后，方法之间的差距小于训练种子之间的标准差。
  - 采样噪声引起的 FID 波动远小于训练种子之间的波动（预计 < 1 FID，而两个种子在 100 步时相差 1.6–20.6）。
  - 2D 的三个种子和种子 0 的结论一致，W2 的标准差小于方法之间的差距。
- **最后要验证的问题**：Q1。“OT-CFM 少步更好”是对方法的结论，还是对某一次训练的结论？
- **判定方法**：三个种子的配对比较（同一种子编号、同一份采样噪声）。只有 3 个种子，符号检验最小 p = 0.125，所以**不报告显著性**，只报告“三个种子方向是否一致”和均值 ± 标准差。方向一致才写成结论；不一致就写成“在我们的训练预算下分不出来”。
- **成本**：训练 3 × 35 分钟（限速时约 55 分钟）；FID 约 1 小时；E3 约 40 分钟；采样噪声约 40 分钟；2D 约 3–4 小时（GPU 占用低）。
- **负责**：共同（A 跑 FM，B 跑 DDPM 和 2D 的 DDPM / DDIM）。
- **输出**：`results/e3/fid_s2.json`、`results/e3/kmeans.json`（追加）、`results/e3/fid_noise.json`、`results/e1/summary.csv`（`n_seeds = 3`）。

### R2. E3 的统计分析加深（必做，只用 CPU 和已有样本）

- **目的**：报告里只给了 TV 和效应量 w。Report 要回答“差异是不是噪声”和“k-means 与 FID 看到的是不是同一件事”。
- **设计流程**
  1. 修改 `cluster_coverage.py`，额外保存每簇计数（现在只存汇总指标），重跑一次（不需要重新训练）。
  2. **TV 的 bootstrap 置信区间**：对 10,000 张生成图有放回重抽 1,000 次，得到 95% 区间；真实测试集同样处理，作为基线区间。
  3. **逐簇检验**：每簇做二项检验（生成占比 vs 真实占比），Bonferroni 校正（10 簇），列出显著偏多或偏少的簇，对照 SVM 标签说明是哪个数字。
  4. **k 的敏感性**：k = 5、10、15、20、30，画 TV 随 k 的变化，并在 k = 10 时报告真实图聚类和真实标签的 ARI / NMI（现有 ARI 0.38）。
  5. **和 FID 的关系**：把所有（方法 × 种子 × NFE）的点画成 TV vs FID 的散点图，计算 Spearman 相关系数。
  6. 附录：TSTR、real-vs-fake 分类器、PCA + Fréchet 距离三个预实验按同一协议（10,000 张、两个种子）重跑一次并保存，作为“为什么选 k-means”的证据。
- **理想结果**
  - DDIM 种子 0 的 TV 区间和其他模型不重叠；种子 1 的区间和 I-CFM / OT-CFM 重叠。
  - 偏多的簇集中在数字 1，偏少的集中在 3（和 slide 28 一致）。
  - 结论在 k = 10–20 之间稳定；k 太大时连真实测试集的 TV 也会变大，所以要和真实基线一起看。
  - TV 和 FID 在少步时正相关（都在看模糊），在 100 步时相关性弱，说明两者衡量的东西不同。
- **最后要验证的问题**：Q5。类别比例的差异有没有超出抽样误差？它提供的信息 FID 能不能代替？
- **判定方法**：bootstrap 区间不重叠才说“不同”；Spearman 相关只描述趋势（点不独立，不做检验）。
- **成本**：生成约 1.5 小时（限速），统计部分几分钟。
- **负责**：A（聚类，课程方法线）；B 负责附录的三个预实验。
- **输出**：`results/e3/kmeans_counts.json`、`results/e3/stats.json`、`results/e3/pilots.json`。

### R3. 采样器和时间网格的消融（应做）

- **目的**：slide 22 在 2D 上说明，少步时的差距主要来自参数化之间的转换和时间网格，而不是路径形状。这一点在 MNIST 上还没验证。另外，DDPM 的标准用法是 1000 步祖先采样，报告里没有这个基线。
- **设计流程**
  1. **DDPM 1000 步祖先采样**：三个种子的 DDPM 网络各生成 10,000 张，算 FID 和 E3 指标。这是 diffusion 一侧的“满配”参照。
  2. **DDIM 的时间网格**：同一个 DDPM 网络，NFE 5 / 10 / 20，比较三种网格：按步数均匀（现在用的）、二次网格（DDIM 论文的 quadratic）、按 τ = a/(a+b) 均匀（和 FM 的时间网格对齐）。
  3. **FM 的高阶求解器**：I-CFM 和 OT-CFM 用 Heun（2 阶），在相同 NFE（2、4、10、20 次网络调用）下和 Euler 比较。
  4. 所有设置用同一份采样噪声。
- **理想结果**
  - DDPM 1000 步的 FID 接近或好于 DDIM 100 步（文献在 CIFAR 上是 3.17 vs 4.16）。
  - 换成 τ 均匀的网格后，DDIM 在 5–20 步的 FID 明显变好，和 I-CFM 的差距缩小；1–2 步仍然失败（除以很小的 a 这个问题不会因为网格改变而消失）。
  - Heun 在 10–20 次调用时比 Euler 好；在 2 次调用时帮助不大（只有 1 个 Heun 步）。
- **最后要验证的问题**：Q2。少步时 FM 和 diffusion 的差距有多少可以靠换网格或换求解器补回来？剩下的部分才归因于路径。
- **判定方法**：和 R1 的种子标准差比较，差距大于两倍标准差才说“改善”。
- **成本**：DDPM 1000 步约 40 分钟 × 3 个种子；网格和 Heun 约 1 小时。
- **负责**：B（diffusion 线），Heun 部分由 A 做。
- **输出**：`results/e5_samplers/`（新目录）。

### R4. Reflow：784 维的一步生成（应做，体现复杂度的主实验）

- **目的**：E2 说明 minibatch OT 在 784 维几乎不改变配对。Rectified flow 的 reflow 用模型自己生成的配对 (x₀, x̂₁) 再训练一次，不受 batch 大小限制。这是 slide 29 的 E4，也是 backup B4 只讲了原理、没有跑的部分。
- **设计流程**
  1. 用 I-CFM 种子 0 的模型，从 60,000 份噪声 x₀ 出发，dopri5 积分得到 x̂₁，保存配对（约 70 分钟；也可用 Euler 100 步，约 40 分钟）。
  2. 用同一个 U-Net、同样的 50 epoch，在配对上用直线目标 x̂₁ − x₀ 训练 2-rectified flow（约 35 分钟）。
  3. 评估：FID 在 NFE 1 / 2 / 5 / 10 / 100；路径长度比（和 slide 27 同一个定义）；直线度 S；E3 的 TV。
  4. 对照组：同样从 OT-CFM 模型做一次 reflow，看两种起点是否收敛到相近的结果。
  5. 配对代价：reflow 配对的 E‖x₀ − x̂₁‖² 和随机配对、minibatch OT 配对放在同一张表里（接 slide 27）。
- **理想结果**
  - 1 步 FID 从 I-CFM 的约 330 降到几十（文献在 CIFAR 上从 378 降到 12.2）；路径长度比接近 1。
  - 100 步时 FID 略差于原模型（配对来自模型而不是真实数据，误差会传下去）。
  - reflow 配对的代价明显低于 minibatch OT 配对（后者只比随机省 4%）。
- **最后要验证的问题**：Q4。在高维中，“直的路径”能不能靠 reflow 得到？少步质量和多步质量之间的取舍有多大？
- **判定方法**：看 1 步 FID 是否低于两个原模型三个种子的最小值；100 步的损失和 R1 的种子标准差比较。
- **成本**：约 2.5 小时（限速时约 4 小时），另需约 3 GB 硬盘存配对。
- **负责**：A。
- **输出**：`results/e5_reflow/`（权重和配对不进 git）。

### R5. OT batch 大小对高维配对的影响（应做）

- **目的**：slide 27 推算，batch 从 128 增大到 2,048 时，OT 节省的代价从 66 增加到 88，但上限只有 2 tr Σ^½ = 386（总代价约 1,509）。这个实验检验这个推算，并看节省的代价能不能变成少步时更好的 FID。
- **设计流程**
  1. 只测配对（CPU）：OT batch = 128、256、512、1,024、2,048、4,096，各算 OT 配对和随机配对的平均代价，画“节省比例 vs batch 大小”，和理论上限对照。
  2. 训练：OT-CFM，训练 batch 仍是 128，但 OT 计划在 512 和 2,048 个样本上求解，再分成小 batch 使用。每个设置 1 个种子（种子 0）。
  3. 评估：FID 在 NFE 1 / 2 / 5 / 10；路径长度比。
- **理想结果**
  - 节省比例随 batch 增大缓慢上升，远低于 2D 的 85–94%，并且明显低于理论上限。
  - FID 在 1–2 步略有改善，5 步以上和 batch 128 没有可分辨的差别。
- **最后要验证的问题**：Q3。高维中 OT 优势消失，是因为 batch 太小，还是因为可以节省的部分本来就很少？
- **判定方法**：如果 batch 2,048 时节省比例仍低于 10%，就说明主要原因是“能节省的部分本来就少”，而不是“batch 不够大”。FID 的差别用 R1 的种子标准差衡量。
- **成本**：配对测量约 30 分钟（CPU）；训练 2 × 约 1.2 小时（OT 求解变慢）；评估约 40 分钟。
- **负责**：A。
- **输出**：`results/e5_otbatch/`。

### R6. CIFAR-10：训练充分的模型（选做）

- **目的**：我们的 MNIST 模型只训练了 50 epoch，没有 EMA，最好的 FID 是 11.5（真实 vs 真实 0.54），还是“演示级”训练。CIFAR-10 的官方权重训练了 400k 步，可以检查我们的结论在训练充分的模型上是否成立。
- **设计流程**
  1. 官方 I-CFM、OT-CFM 400k 步权重；Euler NFE 1 / 2 / 5 / 10 / 20 / 50 / 100 和 dopri5，10,000 张，clean-fid（和 `TEAM_PLAN.md` §7.1 的文献表对照时注明样本数不同）。
  2. 两个模型用同一份采样噪声。
  3. 3,072 维的配对代价（同 R5 第 1 步）。
- **理想结果**：dopri5 下两者接近（文献 3.58 vs 3.66）；少步时 OT-CFM 略好，但差距比 2D 小得多；OT 配对节省的比例比 MNIST 更低。
- **最后要验证的问题**：Q6。“维度越高、OT 优势越小”在训练充分的模型上是否也成立？
- **判定方法**：只有一个训练种子，不下强结论；和文献数字对照趋势。CIFAR 没有同网络的 DDPM 权重，所以 diffusion 一侧只引用文献。
- **成本**：约 2 小时 GPU。
- **负责**：A。
- **输出**：`results/e4/cifar_eval.json`。

### R7. Fashion-MNIST：第二个数据集（选做）

- **目的**：检查 MNIST 上的结论是否依赖于数据集（MNIST 背景几乎全黑，FID 和 k-means 都可能受影响）。
- **设计流程**：三个方法 × 2 个种子，和 MNIST 完全相同的设定；FID 在 NFE 1 / 2 / 5 / 20 / 100；E3 的 k-means 指标。
- **理想结果**：少步时的排序和 MNIST 相同；类别比例的差异更大（衣物类别之间更相似）。
- **最后要验证的问题**：Q6。
- **成本**：训练约 3.5 小时，评估约 2 小时。只有在 R1–R5 完成后才做。
- **负责**：B。
